# Codex 到限后保留完整记录继续对话

## 使用方式

在第三方 Codex 供应商中开启“解除中转站轮次限制”即可，同时启用身份轮换和完整历史归档；“启用会话身份脱敏诊断”仍可独立开关。设置按供应商保存，默认关闭。请求必须经过本地代理并使用原生 Responses 协议。

底层保留 `codexSessionIdentityRotation` 和 `codexSessionHistoryArchive` 两个兼容字段，表单保存时将两者统一写为开关状态。旧配置只开启身份轮换时显示开启，保存后补齐归档；旧配置只开启归档时显示关闭，保存后两者均关闭。打开表单本身不会改写配置。

正常请求保持原样。只有上游明确返回会话轮次上限错误后，本次唯一一次额外重试才会同时使用新会话身份和完整历史归档。同一映射下的后续请求沿用新身份及归档方式。映射位于进程内存，应用重启后会在再次遇到明确上限时重新建立。

## 身份切换提示

本次请求实际触发身份轮换，并且上游完整返回 `completed` 后，代理在回复中加入一条独立中文进度消息，例如“身份已切换（第100轮回复），聊天记录已保留。”。这是回复内的说明，不是客户端原生的“由 ChatGPT 从另一个聊天发送”或“运行了命令”标签；具体外观、进度折叠方式由 Codex 客户端决定。

“第100轮”只使用上游到限错误明确提供的轮数，不代表代理推测的累计轮数。错误没有明确轮数，或中英文轮数冲突时，提示为“身份已切换，聊天记录已保留。”。正常请求、后续稳定复用身份、重试失败、未完成响应和中途断流不生成成功提示。流式正文正常实时传递；提示在确认完成后出现，不会为显示提示而缓存整个回复。

## 保留哪些信息

客户端原始聊天文件不被改写。代理仅调整发送给上游的 `input`：

- 系统指令、开发者指令、用户消息、工具注册、推理密文和压缩密文继续以原生协议条目发送，保持原顺序。
- 历史模型回复、普通工具调用和结果按原顺序分段写入 JSON 归档；不调用模型摘要，不截断正文，不删除工具参数、调用标识或结果。
- 历史消息中的图片、音频、视频和文件等已知媒体继续原生保留；含媒体的工具结果与相同 `call_id` 的调用及结果一起原生保留，保持原位置及关联。媒体不会变成 JSON 文本，也不会删除。
- 原生条目构成分段边界，归档不会把工具定义或开发者指令移到另一个时间位置。
- 将归档中的数组重新展开，可逐项恢复原始 `input` JSON 值。这里保证 JSON 值和内容完整，不保证 JSON 文本的空白、对象键顺序或转义写法相同。
- 当前的工具定义仍然有效，模型可以继续发起新工具调用。工具结果在下一次客户端请求中继续参与完整历史处理。

身份同步另外覆盖正文 `client_metadata["x-codex-turn-metadata"]` 里的已知 JSON 字符串容器，避免外层身份已更换而该字符串仍保留旧会话标识。回合标识、安装标识和其他自定义字段按原语义保留。

## 边界和开销

这项功能改变的是历史输出在协议中的呈现方式。模型仍可读取完整文字和工具记录，原生推理密文仍以原类型发送；它不是创建一个没有历史的新聊天。

归档可能增加输入量，不能保证适用于所有上游。已知媒体及其必要工具关联作为原生分段边界保留，其余文字历史继续归档。旧版遇到历史媒体即停止的限制已修复。遇到尚未支持的非媒体协议类型时仍返回明确错误，保留原始历史，不发送降级后的重试。媒体较多时，上游仍可能拒绝剩余的原生历史；应以实际返回结果判断。

重试仍受原有预算约束：同一客户端请求对同一供应商最多增加一次请求。再次遇到上限即返回错误，不无限循环；普通 400、鉴权、配额及其他错误不触发此归档。

可选脱敏诊断只记录归档条目数、分段数、字节数及会话身份哈希，不记录原始标识、对话正文、密文内容或鉴权凭据。

## 验证重点

归档单元测试需证明逐项恢复、原生指令及工具注册边界、推理和压缩密文保留、混合媒体及工具调用配对保留、重复应用不增加归档，以及未知内容的停止边界。转发测试需证明正常首发不变、明确到限后仅重试一次、后续请求复用映射和归档、连续到限停止。

真实验证不能只检查 HTTP 200：还需确认模型能回答旧历史中的具体信息，并能发起新工具调用和使用返回结果。真实实验记录与安装后同一对话的验证结果应单独保存，不用模拟测试替代。

# CC Switch v4.0.38-codex-auth-142

合入上游 v4.0.38 及后续提交至 `4ef1490e3`，并修复本次源码审查确认的 19 项问题。其中 17 项继承自上游，2 项来自 fork 的网关配额与 Smart 路由逻辑。

## 修复内容

- **供应商与账号数据**：阻止删除或取消同步仍被直连、路由引用的统一供应商；统一供应商及其子记录通过事务删除。账号表遇到解析或读取错误时返回错误，避免将原有多账号表覆盖为空表。
- **代理连接与协议**：转发不再自动跟随携带凭据的重定向。停止代理时拒绝旧连接上的新请求，并在有限时间内收尾连接。增加连接预算和请求头超时；限制未完成 SSE 事件的缓冲，超限返回错误。原生用量采集支持多行 `data:` 和流结束时的尾事件。
- **网关配额与账号选择**：先归一缓存输入语义，再计算不含缓存读的 token 配额。相同用量在 Claude、Codex、Gemini 上保持一致；纠正保留明细的历史账本，保留历史费用与时间。Smart 路由优先选择有额度的账号，即使其重置时间未知。
- **Skills 迁移与恢复**：迁移前检查全部目标冲突，保留隐藏文件与链接身份；设置提交或应用投影失败时保留原来源。上传与恢复共用归档预算，计入隐式目录和条目开销，采用流式读取。恢复失败时精确回滚 Skills，避免把外部链接目标物化为普通文件。
- **云同步**：每次上传写入独立快照，最后发布清单；服务支持强 ETag 时使用条件更新，避免并发上传混合数据库和 Skills。
- **编辑与搜索**：无效 JSON 草稿阻止提交，避免保存旧表单快照。工作区和每日记忆编辑器离开前确认未保存内容，保存后清除脏状态。每日记忆搜索正确处理 Unicode 小写展开和原文预览位置。
- **macOS 凭据**：超长 Claude、Antigravity 凭据通过系统钥匙串 API 写入，不再出现在进程参数中；更新既有条目时保留访问控制。

## 同步兼容性

新上传使用 **v3 同步格式**，数据库兼容版本保持 6。新版仍可恢复支持的 v2 备份；旧客户端无法读取 v3 新快照，请将参与同步的客户端一并升级。原 v2 命名空间保留。

每次上传保留独立快照，目前没有自动清理远端历史快照。服务不提供强 ETag 时，清单仍按最后写入者更新，但不会交叉覆盖不同上传的数据库与 Skills 文件。

## 上游更新

包含 WorkBuddy 一键导入、Antigravity Linux 账号切换、DeepSeek Harness 供应商修复、会话搜索和用量改进，以及 Codex OAuth 路由的 GPT-6.2 提示缓存优化。采用上游的新模块与测试文件结构、共享 Skills 行解码，以及对测试目标的 Clippy 检查。上游删除的工作流、旧搜索依赖、旧 Objective-C 依赖和无用导出已同步清理；保留 fork 的 Codex 路由、会话子代理保护和更新地址。

上游详细说明：[v4.0.38 中文说明](https://github.com/farion1231/cc-switch/blob/v4.0.38/docs/release-notes/v4.0.38-zh.md)。
